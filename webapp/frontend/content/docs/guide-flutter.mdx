The runtime drives Flutter through `flutter run --machine`, so hot reload, hot restart and the app's log all come from the Flutter tool itself.

<Steps>
<Step title="Install Flutter and the Android parts">
```powershell
umr plan .
umr install .
umr trust .
```
The Flutter SDK version follows your `pubspec.yaml` constraint.
</Step>
<Step title="Run it">
```powershell
umr run
```
</Step>
<Step title="Edit and save">
Saved Dart files hot-reload by themselves. Use a restart when state must reset, and a full reload after native changes (Gradle files, plugins, `android/`):
```powershell
umr reload restart
umr reload full
```
</Step>
</Steps>

<Callout type="note" title="Faster second runs">
When nothing native changed since the last build, `umr run` reuses the last debug APK; when that exact APK is already on the device, it attaches to it instead of reinstalling.
</Callout>

Dart compile errors appear with their file and line. Flutter framework errors ("EXCEPTION CAUGHT BY …") and unhandled Dart exceptions appear once each, located at the widget that caused them or the first frame in your own code.
